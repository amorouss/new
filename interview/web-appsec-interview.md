# Web AppSec interview drill

جواب را حفظ نکن. هر جواب باید ۳۰ تا ۶۰ ثانیه باشد: تعریف کوتاه، یک مثال، یک دفاع.

روش تمرین روز ۲۷: تایمر، جواب بلند، بعد مقایسه با outline.

---

## A. متدولوژی

### 1. یک اپ وب را از کجا شروع به تست می‌کنی؟

Outline:

- اول نقشه: نقش‌ها، اشیاء، جریان‌های حساس
- بعد authn در برابر authz
- بعد object id و function-level access
- بعد input → sink (XSS, injection, SSRF)
- ابزار بعد از سؤال می‌آید، نه قبل از آن

### 2. فرق authentication و authorization؟

- Authentication: تو کیستی
- Authorization: اجازه داری این object/action را انجام بدهی
- بیشتر باگ‌های واقعی روی دومی‌اند: لاگین درست است، چک مالکیت نیست

### 3. Broken Access Control را چطور روش‌مند تست می‌کنی؟

- دو حساب هم‌سطح + یک حساب بالاتر
- شناسه‌ها را در URL/body/header عوض کن
- قابلیت مخفی UI را مستقیم صدا بزن
- method و content-type را عوض کن
- مرحله آخر فلوهای چندمرحله‌ای را جدا تست کن

### 4. اگر فقط UI دکمه ادمین را مخفی کند، چه می‌گویی؟

- این کنترل نیست
- اگر API همان عمل را برای کاربر عادی انجام دهد، vertical privilege escalation است
- دفاع: enforcement سمت سرور روی هر درخواست

### 5. IDOR را چطور برای مدیر محصول توضیح می‌دهی؟

- کاربر با حدس یا دیدن یک شماره، داده کس دیگری را می‌بیند
- مثال: `/invoices/124` به جای فاکتور خودش
- اثر: نشت PII یا تقلب
- اصلاح: سرور باید مالکیت را چک کند؛ مخفی کردن عدد کافی نیست

## B. XSS و سمت کلاینت

### 6. XSS یعنی چه و سه نوع اصلی؟

- اجرای جاوااسکریپت مهاجم در مرورگر قربانی
- Reflected، Stored، DOM
- Stored معمولاً اثرش پایدارتر است چون قربانی‌های بعدی هم می‌بینند

### 7. چرا «اسکریپت را فیلتر کنید» دفاع بدی است؟

- Context مهم است؛ فیلتر بلاک‌لیست دور می‌خورد
- دفاع درست: encoding متناسب با context + CSP به‌عنوان لایه اضافه
- sanitizer فقط وقتی مدل HTML لازم است، با کتابخانه نگهداری‌شده

### 8. DOM XSS با reflected XSS چه فرقی دارد؟

- DOM: منبع و sink در مرورگر است؛ سرور ممکن است payload را حتی نبیند
- باید `location`, `innerHTML`, `document.write` و مشابه را ریویو کنی
- Burp + خواندن JS، نه فقط پارامترهای کلاسیک

### 9. CSP چه چیزی را حل می‌کند و چه چیزی را نه؟

- اجرای اسکریپت ناخواسته را سخت می‌کند
- access control، IDOR، SSRF را درست نمی‌کند
- `unsafe-inline` و wildcard تقریباً ارزش را از بین می‌برند

### 10. یک XSS self-xss را گزارش می‌کنی؟

- معمولاً به‌تنهایی impact کمی دارد
- اگر با CSRF، clickjacking، یا یک جریان واقعی ترکیب شود، ممکن است بالا برود
- در مصاحبه بگو: impact را می‌سنجم، اسکنر را با امتیاز اشتباه پر نمی‌کنم

## C. Injection

### 11. SQL injection را در code review چطور پیدا می‌کنی؟

- دنبال concatenation در query، raw SQL، `order by` پویا
- ORM امن است مگر raw / unsafe API
- تست: پارامتر را از data جدا کن؛ اگر syntax عوض شد، مشکوک است

### 12. Blind SQLi یعنی چه؟

- پاسخ دیتابیس مستقیم دیده نمی‌شود
- سیگنال: زمان، تفاوت true/false، خطای کنترل‌شده
- اثر همچنان می‌تواند استخراج داده باشد؛ فقط کانال فرق دارد

### 13. SSTI با XSS چه فرقی دارد؟

- SSTI سمت سرور template را اجرا می‌کند؛ می‌تواند RCE شود
- XSS سمت مرورگر است
- اگر ورودی داخل `{{ }}` یا مشابه برود، اول SSTI را فرض کن

## D. CSRF / CORS / Cookie

### 14. CSRF را ساده توضیح بده.

- مرورگر درخواست authenticated را به سایتی که session دارد می‌فرستد
- قربانی لاگین است؛ مهاجم سایت دیگری را باز می‌کند
- دفاع: token ضد CSRF، SameSite مناسب، برای APIهای حساس ترجیح auth غیرکوکی

### 15. SameSite=Lax کافی است؟

- خیلی از GETهای ساده را بهتر می‌کند
- فلوهای state-changing با GET را نه
- cross-site POST در بعضی سناریوها هنوز مطرح است
- لایه است، نه کل دفاع

### 16. CORS اشتباه رایج؟

- `Access-Control-Allow-Origin: *` با credentials
- reflect کردن Origin بدون allowlist
- اعتماد به origin `null`
- CORS یک مکانیزم خواندن cross-origin است، جایگزین CSRF نیست

### 17. سه پرچم مهم cookie؟

- `Secure`: فقط HTTPS
- `HttpOnly`: JS به session نرسد
- `SameSite`: ارسال cross-site را محدود می‌کند
- هیچ‌کدام authorization object را جایگزین نمی‌کنند

## E. JWT / OAuth

### 18. JWT را روی تخته توضیح بده.

- سه بخش: header, payload, signature
- signature ثابت می‌کند payload دستکاری نشده
- اگر سرور امضا را چک نکند، هر payloadی پذیرفته می‌شود
- claimها: `exp`, `iss`, `aud`, نقش‌ها — ولی نقش داخل JWT جای چک سرور را نمی‌گیرد اگر کلید لو برود

### 19. سه باگ رایج JWT؟

- پذیرش `alg=none`
- algorithm confusion (مثلاً RS256 به HS256 با کلید عمومی)
- `kid` که فایل یا کلید مهاجم را انتخاب می‌کند
- secret ضعیف

### 20. OAuth را در ریویو از کجا می‌بینی؟

- `redirect_uri` دقیق باشد، نه prefix باز
- `state` یا PKCE
- token در fragment/query لاگ نشود
- scope بیش از حد به کلاینت داده نشود

## F. SSRF / API

### 21. SSRF چیست و چرا در cloud بد است؟

- سرور به آدرسی که کاربر می‌دهد درخواست می‌زند
- می‌تواند سرویس داخلی یا metadata را ببیند
- دفاع: allowlist، قطع redirect، شبکه جدا، بلاک metadata

### 22. BOLA یعنی چه؟

- Broken Object Level Authorization
- همان IDOR در API: `/api/users/88/orders` بدون چک مالکیت
- تست: دو توکن، یک object id

### 23. Mass assignment؟

- کلاینت فیلدهایی مثل `role` یا `price` را در JSON می‌فرستد و سرور bind می‌کند
- دفاع: allowlist فیلدهای قابل‌نوشتن، DTO جدا

### 24. Rate limit کجا اجباری است؟

- login، reset password، OTP، کارت‌به‌کارت/پرداخت، export سنگین
- نبودنش یعنی brute force یا abuse، حتی اگر «باگ تزریق» نباشد

## G. نقش شغلی و قضاوت

### 25. فرق AppSec و pentester؟

- Pentester: زمان‌محدود، یافته، گزارش
- AppSec: در SDLC می‌ماند؛ تهدید، ریویو، طراحی کنترل، mentorship
- برای استخدام ترکیبی: بگو هر دو را می‌فهمی ولی می‌توانی با تیم محصول حرف بزنی

### 26. یک یافته Medium را چطور اولویت می‌دهی؟

- exploitability واقعی
- داده / عمل تحت تأثیر
- پیش‌نیاز (auth، user interaction)
- تعداد کاربران
- وجود کنترل جبرانی

### 27. اگر دولوپر بگوید «id را UUID کردیم، IDOR بسته است»؟

- UUID حدس را سخت می‌کند، authorization نیست
- اگر UUID از پاسخ دیگر نشت کند، همچنان قابل‌دسترسی است
- چک سرور همچنان لازم است

### 28. اسکنر خودکار کجا شکست می‌خورد؟

- business logic
- access control چندنقشی
- race
- auth پیچیده
- برای همین چک‌لیست دستی و ابزار خودت مکمل‌اند، نه جایگزین

## H. Behavioral

برای هر کدام داستان STAR آماده کن (Situation, Task, Action, Result). اگر تجربه کاری کم است، از لاب و write-up همین ماه استفاده کن؛ دروغ نگو.

### 29. سخت‌ترین باگی که پیدا کردی چه بود؟

- چه چیزی اول غلط به نظر می‌رسید
- چطور روش را عوض کردی
- impact و remediation

### 30. وقتی با دولوپر مخالفت کردی چه کردی؟

- روی ریسک و شاهد، نه روی غرور
- مسیر exploit را کوتاه نشان بده
- گزینه اصلاح عملی بده

### 31. چطور یاد می‌گیری؟

- اشاره به این اسپرینت: لاب → گزارش → ابزار
- یک مثال مشخص: «JWT را فقط نخواندم؛ analyzer و write-up ساختم»

### 32. چرا امنیت وب؟

- یک جمله صادقانه + یک مهارت که از توسعه/کنجکاوی آمده
- از کلیشه «از بچگی هکر بودم» پرهیز کن
